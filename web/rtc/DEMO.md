# DEMO · 3 分钟演示脚本（前端通话台）

> 目标：让评委在 **3 分钟**内看懂"这不是一个网页，是一条实时语音链路的控制台"。
> 全部零依赖：不需要 GPU、不需要后端（自带 mock）、不需要云端 Key。

---

## 0. 起服务（30 秒）

```bash
node web/rtc/mock/mock-server.mjs          # 零依赖 mock：静态页面 + POST /sessions + 手写 WS
```

打开（**必须 `127.0.0.1`**，用局域网 IP 浏览器会拒麦克风）：

```
http://127.0.0.1:8099/
```

> 页面默认**同源**连后端，所以不用带 `?app=`：由 mock 托管就连 mock，由后端（8081）托管就连真后端。只有"页面和后端不同源"时才需要 `?app=http://HOST:PORT`。

接真后端：把页面换成后端托管的那一份即可——`http://127.0.0.1:8081/rtc/`（`app/main.py` 已把 `web/` 整个目录挂到 `/`）。**代码零改动。**

三种音源模式（按现场条件选）：

| 场景 | URL 参数 | 说明 |
|---|---|---|
| 正常麦克风 | 默认 | 点「开始通话」时浏览器弹权限，允许即可 |
| 无麦克风（保险） | `&uplink=file` | 用 `fixtures/demo_16k.wav` 灌进同一条采集管线，VAD/打断照常 |
| 只想看字幕 | 直接用底部输入框 | 发 `text` 消息，走 text 模式 |

## 1. 演示动线（5 步，每步配一句台词）

### ① 点「开始通话」→ 自检与建链（对应评分维度 5：工程质量）

屏幕出现：`transport: ws_pcm · 媒体未配置`、`session: s_xxxx`、`release: rel_mock_01`、`transport: ws_pcm` 角标。

> 台词："先自检再拨号。媒体服务（LiveKit）现在没配，所以 `/rtc` 返回 503，前端**静默回落到 ws_pcm**——这是契约里写死的降级路径（C1），现场任何一段不通都不影响演示。"

### ② 开场白自动播报（对应额度 1：首字时延）

屏幕出现：用户侧空、数字员工第一句字幕 + 六阶段进度条点亮「① 身份披露」；顶栏状态灯从 `GREETING` → `SPEAKING`。

> 台词："开场白是服务端驱动的，前端只做三件事：字幕、播放、埋点。注意字幕右上角有『游标：估算』——因为当前 Fake TTS 给不出真实音频时间轴，契约里 `tts_alignment=false`，我们不假装精确。"

### ③ 点「模拟打断」（对应评分维度 1：打断响应，**最硬的一枪**）

屏幕右下的调试面板会立刻出现三个数字：

```
b0（VAD 首帧）      ≈ 1234ms
b3（末帧播出）      ≈ 1320ms
打断停止时延         = 86ms
```

同时：Agent 那句字幕被打上删除线 + 标「被打断」；下行波形立刻塌陷；顶栏回到 `LISTENING`；服务端回 `turn_aborted(BARGE_IN)`。

> 台词："打断是前端先动手、服务端再确认。本地 VAD 命中后 **80ms 内**就把播放压到 0，同时把 `b0/b3/played_ms/第几句第几字` 一起发上去——所以打断时延是『用户耳朵听到的』，不是『服务端以为的』。这两个数字差一个 RTT，答辩时被问到能说清。"

**加分动作：打断后什么都别说**，等 ~2.6 秒。屏幕会自己出现一句：

> 数字员工：「请问您对刚刚的话有什么疑问吗？」

> 台词："这是**服务端**在打断后静默超时补的固定话术，走的是正常的 `agent_text + tts_*` 通道，前端没有任何硬编码。用户一开口，服务端就撤掉这个计时器——所以它既不会一直追问，也不会让用户对着静音干等。"

### ④ 打一句文本 / 说一句话（对应评分维度 2、3：任务闭环）

输入框敲「我想改一下配送时间」回车。屏幕出现：

- 用户字幕 → 数字员工追问 → 工具卡片 `order.query · calling → ok · 138ms`
- 合规面板出现一条 `REWRITE`：`保证今天一定送到` → `以实际配送结果为准`
- 六阶段进度条推进到「④ 方案沟通」

> 台词："工具调用、合规改写都是服务端下发的，前端只负责让它**看得见**。合规这条是 REWRITE：拦下来改了再播，不是播完才检。"

### ⑤ 任务完成 → 结果卡（对应评分维度 2：结构化回写）

进度条拉到「⑥ 回写完成」，右侧结果卡出现 `outcome: rescheduled` / `ticket: pending`。

> 台词："回写是这一轮的唯一物证。真实抓包里这块是嵌套的 `result.result.ticket`，我们做了归一化——契约里原来写的是扁平结构，这是抓包发现的差异之一。"

## 2. 只念这 5 个数字（评委只会记数字）

| 位置 | 指标 | 目标 |
|---|---|---|
| 顶栏 | `rtt` | < 100ms（同机） |
| 调试面板 | 首字时延（`playback_first_frame`） | P50 ≤ 2s（硬门槛） |
| 调试面板 | 打断停止时延 | ≤ 100ms（用户可感） |
| 合规面板 | 命中条数 / 改写前后对照 | 必说 100%，禁语召回 100% |
| 结果卡 | `outcome` + `ticket` | 有值 = 闭环成立 |

---

## 3. 翻车预案（现场必背）

| 现象 | 原因 | 处理 |
|---|---|---|
| 点开始通话没声音 | 浏览器自动播放策略：必须先有用户手势 | 已经做成"点按钮才出声"，别用页面加载就自动播 |
| 麦克风被拒 | 用了局域网 IP / http 非 localhost | 换 `127.0.0.1`，或加 `&uplink=file` |
| 完全没有声音但字幕在动 | 浏览器 `speechSynthesis` 被禁（部分 Linux） | 换 Chrome/Edge；或 `&downlink=pcm` 等真 TTS |
| 打断后还有半句 | 服务端没清推流缓冲 | 前端已作废旧 `reply_id`，报告里写"服务端取消延迟" |
| 页面刷新后连不上 | `session_id` 丢了 | 重新点「开始通话」（不要刷新，演示前禁用 F5） |

## 4. 这是"前端"为什么能撑起 3 分钟

不是因为它好看，是因为**整条链路的证据都在这一屏上**：谁在说、说到第几字、被打断时多少毫秒、工具调了什么、合规改了什么、结果回写了什么。评委打断你的演示时，你能指着屏幕上的数字回答"发生了什么"。
