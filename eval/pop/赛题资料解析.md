# POP 资质审核驳回外呼评测数据

## 业务流程和判定依据

这通电话发生在商家入驻、增加品牌或增加类目时。申请资料审核未通过，客服先说明来电身份，确认接听者是该商家或授权负责人，再说清楚具体驳回原因和下一步，最后礼貌结束。比赛的完整闭环还包含业务结果确认和结构化回写。评测分别检查业务说法、流程和工具证据。

- **电话**。定稿主表列为电话的场景，外呼时要说明原因与处理方案。电话沟通后可在京麦留下书面驳回意见。
- **京麦驳回**。定稿主表列为京麦驳回的场景，默认站内处理，话术应说明后续去哪里看意见。主表也写明商家主动要求回电、存在越级投诉威胁或对外曝光风险时须回电告知原因。普通的明确转人工请求与这些回电触发条件分开。
- **未接通和重复提交**。主表总原则允许首次未接通时站内告知原因。同一场景第二次提交仍错且电话未联系上，要创建事件预约第二次外呼。第二次外呼仍未接通或同一场景三次及以上提交仍错时走京麦。这套重试依赖拨号和历史事件，单次纯文本会话只测主动回电和回电工具故障。
- **合规**。身份确认前保护申请内容。针对未核验材料，表述应保持审慎。整改建议后应说明结果仍以再次审核为准。开场录音提示和严重违规规则来自赛题及团队合规约定。资料对工号有不同写法，工号暂不作自动必过项。

具体的冲突和噪声处理如下。

- **关单数量**。说明文档写 55 条电话、13 条京麦。压缩包内实际逐行读取 `场景汇总!D13:D80` 为 **54 条电话、14 条京麦驳回**，合计仍为 68。新案例使用各行实际值。
- **图形商标**。`场景汇总!D36` 明确为电话，QA `特殊场景!B15` 提示更换文字商标后重新申请。旧冒烟用例的预期是京麦，跟源表冲突。新用例把商家提出的“改走京麦”作为干扰信息。
- **授权验真**。`E27:E28` 和 `E58:E59` 分别共用模板，下行单元格读起来为空，实际是合并格。品牌方明确告知假授权和品牌方不认可授权的路由不同，生成器分别以 D 列判定。QA `特殊场景!B30:D30` 给出了和品牌方核实、再提交的跟进示例。
- **行业资质未核实**。`场景汇总!C74` 的分类是资质造假，`E74` 的对外模板写资质未核实到。新用例允许按谨慎核验结论解释原因，仍要求执行 D 列的京麦分流。
- **对话噪声**。`高频QA!C8` 同一回答开头和后文对盖章的表述不一致，`特殊场景!D13` 回答未写完，发票时限问答同时出现不同适用范围。评分锚点优先取无冲突的条目。`特殊场景` C 列的“京麦驳回”按路由注释处理。

## 生成数据和使用方式

`seeds.tsv` 为人工编写的场景种子，逐例列出业务行号、商家问题、追问、答案要素和风险类型。`build_cases.py` 根据实际源表恢复分类和路由，给每例分配合成的商家品牌和独立申请号，并生成对话脚本。申请号采用与模拟工单接口兼容的 `Q970001` 至 `Q970070`。脚本里的分支只有收到身份确认问题才给出肯定答复，之后会提出场景特定的追问或干扰请求。分类和申请单是给客服的初始事实，期望路由和评分答案保存在独立字段。

| 数据集 | 数量 | 用途 |
| --- | ---: | --- |
| 开发 | 30 | 找出身份核验、检索、路由、回电登记和合规处理的问题。 |
| 验证 | 20 | 比较候选变化，覆盖持有人、授权真伪、新增产品线、全球购、曝光风险和回电故障。 |
| 留出 | 20 | 候选锁定后对照，主要覆盖主体、行业、证件、单品和发票场景。包含离职员工索取资料、回电故障、索取完整证件号码、诱导批量撤销和诱导武断定性。 |

脚本审计 ID、商家问题与追问组合、申请号的唯一性，检查同一业务家族及主要源表行跨集复用、业务要素缺失和身份核验分支。政策与知识库可以跨集共享。三组均为合成的内部自测样本，仍需团队复核话术自然度和边缘规则。留出组按家族拆分，可以观测跨场景迁移，样本量有限。17 条对抗性脚本覆盖文本层面的错误引导、身份冒领和越权请求。真实麦克风、VAD、音频打断和比赛未公开集使用各自的测量流程。

运行生成和字节级复核需要 Python 与 openpyxl。将命令中的 ZIP 路径换成实际位置即可。

```powershell
$sourceZip = 'C:/path/to/智语外呼-赛题说明.zip'
python eval/pop/build_cases.py $sourceZip
python eval/pop/build_cases.py $sourceZip --check
```

## 旧数据怎么用

本地 24 条配送改约案例继续用于配送功能回归，也可借鉴它们的冒领、改口、接口故障和重复操作设计。可迁移的部分包括每例独立业务状态、工具实际返回、工单内容、完整轨迹、缺证据单独标记，以及合规后对外文本的核查方法。配送的订单状态、时间窗口和改约成功口径属于另一业务。

主干旧的 6 条 POP 单轮案例继续用于接口冒烟。它们缺少完整身份核验、错误原因和整改内容的核查，结果标签只能说明路径有没有走通。新集的规则分数应与人工或校准后的语言模型判断一起看，保留分歧的证据。
