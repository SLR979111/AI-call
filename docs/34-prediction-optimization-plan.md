# 34 · 预测优化方案（规则命中之后）

> 现状：规则引擎在 `feature/rule-engine`；预测/decision 在 `feature/decision-rules`。  
> 本文是方案，不是已实现结论。

## 1. 现状

### PR20

```text
规则不确定
→ 完整模型一次调用
→ 模型同时选候选 + 生成回复
```

实测：

```text
语音直接生成 6 轮：
  P50 1013ms
  P95 2996ms
```

PR20 没有独立 decision 模型；规则失手时，首完整句/正式音频有长尾。

### 当前预测分支

```text
规则不确定
→ 短 decision 选候选
→ 选中：预测音频
→ generate：完整生成
```

文本固定 12 条：

```text
总复用 6/12
规则 2/12
decision 4/12
未命中 6/12
```

语音直接生成 6 轮：

```text
P50 902ms
P95 1129ms
```

注意：这些语音样本是直接生成，不是命中路径；命中路径还没测。

## 2. 目标

```text
规则命中率：2/12 → 4/12
总复用率：6/12 → 8/12
未命中：6/12 → 4/12
不复用/命中路径分别给 P50、P95
```

不接受：

```text
先文本当命中
热缓存冒充冷启动
把未命中样本当命中路径
只报总 P50，不拆规则/decision/未命中
```

## 3. 阶段一：候选生成从“匹配”变成“覆盖”

### 3.1 工单候选

从 TaskCard 自动生成候选：

```text
checkpoint.id / description
facts 中的材料、公司、状态、动作
opening 中的问题
```

每个工单生成固定问法族：

```text
缺什么 / 要补什么
怎么补 / 在哪提交
已提交 / 只保存 / 审核中
公司名 / 名称不一致
截图 / 注册证 / 状态
经销商授权 / 品牌方直授
多久 / 能不能加急 / 能不能过
```

候选需要带标签：

```json
{
  "checkpoint": "authorization",
  "intent": "missing_material",
  "polarity": "question"
}
```

规则用标签和工单短语匹配，候选匹配不再只靠自然语言 `when`。

### 3.2 与模型候选合并

```text
模型候选
+ 工单模板候选
→ 去重
→ 最多 10 条
→ 文本发布
→ 音频后台准备
```

规则模板候选不替代模型，只补“模型没覆盖到的常见问法”。

验收：

```text
规则命中 4/12
规则误命中 0
留出集也命中
```

## 4. 阶段二：decision 路由

不要在规则 `llm` 后无条件调用 decision。

```text
规则高置信
→ 直接复用

候选相关性高
→ decision 只选 id

候选相关性低
→ 跳过 decision，直接完整生成
```

### 4.1 相关性门槛

已有 `decision_relevance` 思路：

```text
用户 2–5 字片段
和候选 when/examples/reply 有重叠
才允许 decision
```

继续加：

```text
候选标签匹配
问句类型匹配
否定/改口排除
```

### 4.2 decision 与生成并行

当前串行问题：

```text
decision 判断 generate
→ 再完整生成
→ 多 0.7–0.9s
```

改成：

```text
decision 和完整生成同时启动
先返回 reuse → 取消生成
先返回 generate/生成完成 → 用生成
```

这样：

```text
命中：约 0.7–0.9s 判断 + 播放
未命中：不额外叠加 decision
```

### 4.3 缓存

decision 请求和完整生成都受缓存影响：

```text
冷启动、热缓存分开报告
不要把热缓存 P50 当冷启动
```

## 5. 阶段三：命中路径实测

### 5.1 场景

| 场景 | 固定输入 | 留出 |
|---|---:|---:|
| 京东资质 | 12 | 8 |
| 官方工单 | 6 | 4 |
| 宽带支持 | 6 | 4 |
| 网络套餐 | 6 | 3 |
| 强对抗 | 6 | 4 |

### 5.2 指标

每个场景分别报告：

```text
规则命中数 / 命中率
decision 命中数 / 命中率
未命中数 / 未命中率
总复用率

规则命中语音 P50/P95
decision 命中语音 P50/P95
未命中语音 P50/P95
总 P50/P95
```

语音口径：

```text
最后一帧人声
→ 静音判停
→ ASR
→ 第一段正文音频开始播放
```

文本命中率可以用于规则评估，但不能替代语音 P50/P95。

### 5.3 基线

```text
PR20 d46938f
当前无 decision
当前 decision
当前 decision + 相关性门槛
当前 decision + 并行 + 工单候选
```

## 6. 验收标准

```text
规则命中：≥4/12
总复用：≥8/12
规则误命中：0
留出集：不低于拟合集 20 个百分点
命中路径 P50：不高于未命中路径
总 P95：不高于当前基线
```

如果 decision 串行仍拖慢：

```text
只保留规则快路径
decision 改为并行或仅高相关候选
```

## 7. 实施顺序

```text
1. 工单模板候选 + 标签
2. 规则命中回归（拟合/留出）
3. decision 只对高相关候选
4. decision 与完整生成并行
5. 多场景语音基准，拆规则/decision/未命中
6. 与 PR20 严格同标准对比
```

## 8. 非目标

```text
不改 ASR
不改 TTS
不改 VAD
不承诺审核结果
不把文本首字时间当命中收益
```

## 9. 风险

```text
规则模板候选可能重复/冲突
decision 可能误选
并行生成增加模型成本
热缓存导致假快
测试集过拟合
```

对策：

```text
去重和候选上限
高相关才 decision
失败/超时回退
冷/热缓存分开
拟合集/留出集分开
```
