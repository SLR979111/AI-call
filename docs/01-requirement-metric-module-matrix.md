## 2. 评分维度解码与策略

官方权重未公布。策略：**任何维度不拿 0 分**，把资源压在「实时语音 + 任务完成 + 合规」三条门槛相关维度，用 RSI 和 Flow Pack 拿创新分。

| 官方维度 | 官方评价点 | 我方指标族 | v0.1 策略 |
|---|---|---|---|
| 1 实时语音交互质量 | 打断响应、P50/P95 时延、VAD 准确度、双讲抗噪、自然度可懂度 | 首字时延、打断停止时延、端点准确率、CER、MOS | 主攻：首字 P50 ≤1.2s、打断停止 ≤300ms；AEC 用浏览器 + 耳麦兜底 |
| 2 任务完成能力 | 意图、槽位、闭环率、多轮纠错与主动追问 | 意图准确率、槽位 F1、闭环率、纠错成功率 | 状态机约束流程，LLM 只做理解与表达；每个槽位有追问模板 |
| 3 业务知识与工具调用 | 知识准确率与可溯源、工具正确率、回写完整度 | RAG 准确率、引用率、工具参数正确率、回写合法率 | 知识必须带来源；工具只走 Gateway；回写做契约测试 |
| 4 合规与全量质检 | 必说话术、禁语拦截、质检报告完整可用 | 必说话术覆盖率、禁语召回、误杀率、QC 报告完整度 | 三层合规（见 02 文档）；质检报告自动生成 |
| 5 工程质量与创新性 | 架构合理可复现、时延成本、技术亮点 | 一键启动、复现偏差、成本/通话、事件覆盖 | Flow Pack + RSI 是主创新点；不堆基础设施 |
| 6 跨学科协作 | 背景覆盖、分工、贡献、答辩取舍 | RACI、贡献记录、答辩脚本 | 架构师维护 ADR 与答辩材料，避免「只有一个人在讲」 |

> 同分 tiebreak 第一位是 **RSI 进化有效性**。这意味着 RSI 不是「做了就行」，而是要有**基线 vs 候选的可复现对比数据**。从 Stage 1 起就要为它预留数据结构和版本字段。

## 3. 关键指标定义（只展开容易口径不一致的）

### 3.1 时延时间轴

```text
t0  用户最后一个有声帧（VAD 判定）
t1  VAD 端点触发（endpointing）
t2  ASR final 产出
t3  Agent 开始处理
t4  LLM 首个 token
t5  首个完整句子可送检（sentence chunker）
t6  合规检查通过
t7  TTS 首个音频包
t8  下行首帧发出
t9  客户端首个音频采样真正播出
```

| 指标 | 定义 | 目标 | 测量方式 |
|---|---|---|---|
| 首字时延（保守） | `t9 - t0` | P50 ≤ 1200 ms `[内]`；P95 ≤ 2000 ms `[内]` | 客户端 `AudioContext.currentTime` + 服务端事件时间；时钟偏移用握手估计 |
| 首字时延（官方代理） | `t9 - t1` | P50 ≤ 2000 ms `[官]` | 同上；同时上报两个值，等官方口径 |
| ASR 收尾时延 | `t2 - t1` | P50 ≤ 150 ms `[内]` | 服务端事件 |
| LLM 首 token | `t4 - t3` | P50 ≤ 500 ms；P95 ≤ 900 ms `[内]` | 服务端事件 |
| TTS 首包 | `t7 - t6` | P50 ≤ 200 ms；P95 ≤ 400 ms `[内]` | 服务端事件 |

> 关键认知：官方只卡 P50 ≤ 2s，但**评分同时看 P95**。P50 达标靠架构，P95 达标靠超时、降级和预热。

### 3.2 打断（Barge-in）

```text
b0  用户打断语音起点（客户端本地 VAD）
b1  服务端判定打断
b2  取消信号到达 LLM/TTS
b3  客户端最后一个 Agent 音频帧播出
```

| 指标 | 定义 | 目标 |
|---|---|---|
| 打断停止时延 | `b3 - b0` | P95 ≤ 300 ms `[内]` |
| 打断识别时延 | `b1 - b0` | P95 ≤ 200 ms `[内]` |
| 打断后残留 | 取消后仍播出的 Agent 音频时长 | = 0（允许 ≤100 ms 淡出） |
| 误打断率 | 噪声触发本地 VAD 的比例 | ≤ 2% |

> 架构规则：**客户端本地 VAD 立即静音**，不等服务端往返；服务端取消是异步补偿。否则 300ms 目标在网络 RTT 上就不可能。

### 3.3 VAD / 端点

| 指标 | 定义 | 目标 |
|---|---|---|
| 端点延迟 | 用户说完最后一个字 → 端点触发 | P50 ≤ 300 ms；P95 ≤ 500 ms |
| 误切率 | 用户句中停顿被误判为说完 | ≤ 2% |
| 漏切率 | 用户说完但未触发端点（靠超时） | ≤ 3% |
| 噪声误触发 | 50 dB 背景噪声下误触发 | ≤ 1 次/分钟 |

### 3.4 ASR / TTS

| 指标 | 定义 | 目标 |
|---|---|---|
| 字错率 CER | 领域测试集，实体做归一化 | ≤ 8% `[内]` |
| 实体准确率 | 姓名/号码/金额/日期/地址 | ≥ 95% `[内]`（比 CER 更贴近业务） |
| 热词命中率 | 领域词表覆盖的词 | ≥ 90% |
| TTS 首包 | 见 3.1 | ≤ 200 ms |
| 自然度 MOS | 5 人盲听，1–5 分 | ≥ 4.0 `[内]` |
| 可懂度 | 关键词听写正确率 | ≥ 98% |

### 3.5 任务 / 知识 / 工具 / 合规

| 指标 | 定义 | 目标 |
|---|---|---|
| 意图准确率 | 多分类，含「其他/转人工」 | ≥ 90% |
| 槽位 F1 | 每槽位 P/R/F1，再宏平均 | ≥ 0.85 |
| 槽位完整率 | 闭环所需槽位齐全的会话占比 | ≥ 95% |
| 任务闭环率 | 六阶段走完 + 回写成功 | ≥ 80% |
| 多轮纠错成功率 | 用户否定/更正后，系统改对 | ≥ 85% |
| 主动追问命中率 | 该追问时追问了正确槽位 | ≥ 90% |
| RAG 准确率 | 答案与标准答案语义一致 | ≥ 85% |
| 引用率 | 回答附带知识来源 | 100% |
| 幻觉率 | 无依据的事实断言 | ≤ 5% |
| 工具选择正确率 | 选对工具 | ≥ 95% |
| 工具参数正确率 | 必填参数与值正确 | ≥ 90% |
| 工具成功率 | Mock API 2xx + schema 合法 | ≥ 98% |
| 幂等一致率 | 同 key 重放结果一致、无重复副作用 | 100% |

| 禁语召回率 | 测试集中禁用话术被拦截 | 100% `[内]`（严重违规 0） |
| 合规误杀率 | 正常话术被误 BLOCK/REWRITE | ≤ 5% |
| 合规判定时延 | 关键路径单句检查 | P95 ≤ 50 ms |

### 3.6 评测 / RSI / 工程

| 指标 | 定义 | 目标 |

## 4. Requirement–Metric–Module 主矩阵

模块代号：

- **M1** 接入与媒体层（浏览器端 + 媒体网关 + 音频 I/O）
- **M2** 实时语音层（VAD/降噪 + ASR 适配器 + TTS 适配器）
- **M3** 实时编排器（会话/轮次/取消/超时/下行队列）
- **M4** Agent 核心（Flow Engine + 上下文 + LLM 决策 + 兜底）
- **M5** 工具网关（RAG 归 M4，Tool Gateway 归 M5）
- **M6** 合规与安全守卫
- **M7** 数据与可观测层（事件总线/存储/回放/看板数据）
- **M8** 评测与 RSI
- **M9** 版本与配置注册中心
- **M10** 演示控制台与前端

### 6.3 孤儿模块 / 孤儿指标

- 孤儿模块：无。M9 服务 R21/R23/R24/R26；M10 服务 R16/R19/R25。
