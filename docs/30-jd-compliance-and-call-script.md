## 2. 京东官方页面明确写了什么

### 2.1 品牌申请入口

```text
京麦后台 → 店铺 → 品牌管理
```

《品牌使用指导手册（个人/个体/普通企业店）》写明：品牌管理只展示已经提交过授权的品牌；没有提交过授权的品牌不会显示。该说明针对个人店、个体店、普通企业店；旗舰店、专卖店、专营店是否适用，以本次申请页为准。

### 2.2 品牌和商标条件

官方页面明确：

```text
必须符合法律法规和京东开放平台规则
不得涉及品牌混淆、侵权、违规或违禁词
必须是在中国或国际注册的有效商标
只受理文字商标，暂不受理图形、声音、气味商标
不得重复创建品牌，品牌形象需唯一
```

商标信息可通过中国国家知识产权局、国际局等官方渠道核验。不要凭截图模糊或口头说法就认定商标有效。

### 2.3 品牌申请的三种身份

《POP 品牌管理常见问题指南》针对旗舰店、专营店、专卖店、卖场店给出三条路径：

```text
品牌方本人
被品牌方授权经营全类目
被品牌方授权经营部分类目
```

官方页面只列了这三条路径，没有逐条列出三种身份的材料清单；“对应不同材料”是操作上的推断，不是逐字规则。

《品牌使用指导手册（个人/个体/普通企业店）》针对个人店、个体店、普通企业店，说明无需主动提交品牌授权，直接在商品发布界面选择品牌；品牌不可选、类目未收录或提示需要授权时，再按页面提交申请或授权材料。

电话里不要把“经销商授权”一概说成平台统一要求；先看本次驳回意见和本次申请页要求。

### 2.4 审核时效

官方页面写的是：

```text
中国品牌且信息与国家注册信息完全一致：系统自动秒审
非中国品牌，或中国品牌信息与国家注册信息不一致：人工审核，页面原文为“预计1个工作日内审核通过”（这是品牌申请审核时效，不等于本次补正复审时效）
着急可联系京东客服催审
```

电话话术必须说成：

```text
官方页面写“预计1个工作日内审核通过”，这是页面参考，具体以实际审核为准
```

不能说“保证今天通过”“加急一定过”“百分百通过”。

### 2.5 品牌资质到期

官方页面明确：

```text
品牌资质到期后商品会被下架
平台会提前 30 天提醒
商家应及时更新/延期
审核通过后，需商家按页面提示自行重新上架商品
```

电话里可以提醒到期风险，但不能承诺审核时间或结果。

### 2.6 品牌名称和 Logo

```text
品牌名称修改：提供盖公章的《品牌名称修改确认函》，发送至 brand-serv@jd.com
品牌 Logo 更新：品牌 ID + 方形 Logo + 长形 Logo + 品牌 Logo 使用确认函，发送至 brand-serv@jd.com
```

具体模板和访问方式以京东页面为准，不在电话里编造附件地址或验证码。

### 2.7 普通企业店、个体店、个人店

《品牌使用指南》说明：个人店、个体店、普通企业店在部分场景下无需主动提交品牌授权，直接在商品发布界面选择品牌即可；但品牌不在可选范围、类目未收录或提示需要授权时，仍要按页面提示提交申请或授权材料。

不能把“普通企业店不用授权”一概套到旗舰店、专卖店、专营店或特定类目。

### 2.8 资质真实性

《京东开放平台招商标准》（2019-10-19 生效版）要求商家如实提供资料和信息，保证真实性、完整性、有效性；第三方提供的商标注册证、授权书等要先核实。发现虚假资质或信息，平台会按规则处理。这里只引用该版本的资质真实性要求；其中“暂不接受个体工商户”等旧条款已被现行个人店/个体店帮助页覆盖，规则中心也有更新的《招商资质标准细则》，不能把整份 2019 文档当现行规则全文。

## 3. 本项目的案例假设，不是京东统一政策

当前演示工单使用虚构公司、品牌和驳回记录。以下内容是**本次案例的假设**，电话里必须说“本次驳回意见/本次材料”，不能说“京东规定所有商家都必须这样”：

```text
禾木商贸有限公司申请青禾品牌
品牌方是青禾品牌公司
经销商是远杉商贸公司
退回意见三项：缺上游授权、授权公司名与店铺主体不一致、商标状态截图模糊
经销商授权需要两段接续
改成品牌方直接授权后，本次案例不再要求经销商那一段
```

其中“两段授权链”“名称必须完全一致”“注册证不能替代当前状态截图”是本次案例和辅助平台资料的审查要点；本次适用的京东 POP 品牌管理帮助页没有逐字写出这套组合。京东全球购店铺资质规范要求“完整销售授权链路/一级授权”，但只适用于跨境店铺；《京东开放平台招商标准》（2019-10-19 生效版）对旗舰店要求独占性授权、授权文件不应有地域限制，也不是本次三项驳回意见的直接依据。对外话术要区分：

```text
官方规则（43743 + 招商标准）：有效文字商标、按身份提交、资质真实完整有效
辅助推断（天猫/拼多多）：授权需在有效期内、多级授权有效期不得超过上一级
（京东帮助页未直接写“授权有效期”）
本次案例：这三项材料具体缺什么、名称差在哪里、截图要看清什么
```

## 4. 电话话术指导

### 4.1 开场

```text
您好，我是协助核对京东店铺品牌资料的第三方客服，不是京东官方审核人员。这次资料想跟您核对一下，您是负责这块的吗？
```

如果对方已经自报身份并直接提问，不再单独走“方便吗”的流程，直接回答。

### 4.2 先确认问题，不要一次念完三项

```text
先确认对方负责这次资料
→ 问本次驳回意见看到哪一项
→ 一次只解释一个卡点
→ 对方改口时更新对应事实
```

### 4.3 三类高频问题的说法

**缺授权**

```text
您这次已经交了经销商给店铺的授权，但本次材料里还缺品牌方给经销商的那一段。
不是说现有授权是假的，是中间少了一环。
```

如果对方说已经改成品牌方直接授权：

```text
如果这次已经换成品牌方直接授权给店铺主体，就按本次申请页的新材料要求提交；
是否接受以本次审核为准，我这里不能替审核下结论。
```

**公司名称不一致**

```text
这份授权上的被授权公司写的是“禾木商行”，本次店铺主体是“禾木商贸有限公司”。
需要原授权方重新开具，或提供能说明名称变更关系的材料；
不要自己涂改、修图或覆盖原文件。
```

**商标状态截图**

```text
需要能看清商标名称、注册号和当前状态的截图。
注册证照片不自动等于当前状态截图；
截图清楚也不代表当前状态一定符合要求。
```

### 4.4 已补交/已提交

用户说“已经补了/提交了”，只能记为用户说明：

```text
您说已经补充并重新提交了，那您留意本次申请的最新提示。
我这里看不到实时审核结果，不能替您确认已经通过。
```

不能说：

```text
材料都齐了
已经核实
审核没问题
今天一定能出结果
```

### 4.5 催审/转人工/回电

```text
我这里不能代查、代提交、转人工或安排回电。
官方页面提到“如实在着急，请联系京东客服催审”，具体入口以京麦本次申请页为准；我这里不能代为催审。
```

不编造热线、菜单、邮箱或办理时限。

### 4.6 收尾

```text
本次要补的就是这几项，您按本次申请页的提示提交后留意最新反馈。
具体审核结果以平台为准。
```

用户明确理解、没有待答问题、材料说明完成，才收尾；普通“嗯/好”不自动算理解。

## 5. 禁用表达

电话和指导文件中禁止：

```text
保证通过
包过
百分百
一定通过
必过
加急一定处理
今天/明天一定出结果
我已经帮您提交/登记/转人工
京东商家资质审核客服
我是京东官方审核人员
已帮您催审
```

官方页面的“预计1个工作日内审核通过”只针对品牌申请审核，不等于本次补正复审时效；只能作为参考，不能说成承诺。

## 6. 对预测候选的约束

预测候选必须遵守同一套合规边界：

```text
when 只写用户实际可能说出的条件和限制
examples 必须是用户可能说出的完整短句
reply 不承诺审核结果、时限、加急、代办
不把用户自述“已提交/已补交”写成系统已核验
不把“本次案例假设”说成京东统一政策
不编造截图入口、热线、菜单、邮箱
```

除提示词约束外，`new/app/session.py` 在发布预测候选前还会做一次拦截：候选回复包含“保证通过、包过、百分百、一定通过、必过、今天一定、明天一定、已帮您提交、已转人工、京东官方审核人员”等表达时直接丢弃，并记录 `prediction_compliance_drop`。这是兜底，不替代提示词约束。

建议候选带回答标签（肯定、否定、已准备、未准备、已提交、未提交、名称已更正、看不清、不明白、忙、结束、其他），规则匹配使用“上一句问句类型 + 用户标签 + 候选标签”，不要继续堆京东业务词。

## 7. 预测文本与音频解耦

当前 `new/` 预测链路改为：

```text
候选文字一到 → 立即发布文本候选
             → 同时后台准备音频
             → 音频准备好后存入服务端候选缓存（同一句文本对应一段音频）
             → 不会再次推送候选
             → 用户短答命中复用时才取用；没有音频就回退普通语音合成
```

这样用户能更早看到/选择文本候选，不必等全部音频合成完；代价是选中未准备好音频的候选时会走普通语音合成，接话时间会增加。

`PREDICTION_AUDIO_LIMIT` 只限制“预合成几条音频”，不阻止文本发布。具体合成几条要按真实候选命中分布决定，不能只看离线脚本。

当前决策：**默认保持 all（不设置上限）**。真实日志里被复用的候选到达排名是 1、2、4、5、5、6、7、7、7；如果按到达顺序只预合成前 3 条，语音复用命中会从 5/5 掉到 0/5；前 5 条也只有 3/5，另外 2 轮会回退普通语音合成，增加约 2–3 秒静默。先把候选排序改成“命中优先”，再考虑限制条数；不要直接按到达顺序设 N=3。
