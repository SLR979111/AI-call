# 16 · POP 资质审核驳回外呼场景

> 数据来源：赛题《[POP资审]资审关单场景话术 V1.0.xlsx》《驳回外呼QA.xlsx》《赛题数据说明.docx》。
> 场景：京东 POP 商家在入驻、新增品牌或新增类目时，品牌资质审核未通过，由资质审核专员电话外呼说明驳回原因与整改动作。

## 2. 业务结构

一通合格的电话是四段式：

1. **自报身份**：京东商家资质审核专员，说明通话录音；
2. **确认商家身份**：确认公司/店铺负责人，不能打错人；
3. **说明驳回原因 + 整改动作**：对应三级分类和标准话术；
4. **礼貌结束**：感谢接听，留统一热线 4006180092。

关单方式分两类：

| 方式 | 适用 | 处理 |
|---|---|---|
| 电话 | 可补齐、可重新开具、需指导操作 | 必须外呼说明原因与处理方案 |
| 京麦驳回 | 造假、治理停用、无品牌、平台不予招商等 | 站内驳回并留书面意见，不强制回电 |

未接通/重复错误规则：

- 首次电话未接通：可先京麦驳回并告知原因；
- 同场景二次仍错且未接通：创建事件，预约二次外呼；
- 二次外呼未接通：执行京麦驳回；
- 三次及以上相同场景错误：均走京麦驳回；
- 商家主动要求回电、越级投诉威胁或外部曝光风险：一律回电。

## 3. 数据结构

### 3.1 场景话术（制度层）

主表字段：

```text
一级菜单 → 一级分类 → 二级分类 → 关单方式 → 资质驳回商家参考话术
```

- 主表 68 条场景；其中 2 条只有分类、没有话术模板，知识库收录 66 条可用模板。
- 电话 55 条、京麦驳回 13 条（以主表口径计）。
- 话术形态：固定开头 + `【】` 占位符 + 固定结尾 + 热线。

知识库落盘：`knowledge/pop_audit.json`。

### 3.2 外呼 QA（执行层）

| 工作表 | 内容 | 用途 |
|---|---|---|
| 驳回话术 | 52 条整句话术 | 电话外呼体，含身份确认、感谢接听 |
| 高频QA | 11 组 | 操作路径、门槛、质疑、知识来源、结果预期 |
| 特殊场景 | 28 条剧本 | 一句标准话术 + N 个商家追问 |

知识库同时收录这些条目，供 RAG 检索与话术参考。

## 5. 商家追问的五类意图

从 QA 数据归纳：

1. 操作路径：在哪里改、店铺名怎么改；
2. 门槛标准：类目怎么申请、数量/金额、发票有效期；
3. 质疑合理性：我这是真授权、品牌方固定模板改不了；
4. 知识来源：在哪查商标状态、怎么分辨图形商标；
5. 结果预期：补上来就能通过吗。

Flow/Agent 的追问处理应覆盖这五类，而不是只背一句驳回模板。

## 6. 数据质量与使用边界

赛题说明已指出这些数据是真实业务文档，不是训练集，使用时要处理：

- 三级分类合并单元格需要向下填充；
- 场景标签残缺，不能当分类字段；
- `【】`/`【XX】`/`【XXX】` 占位符不统一；
- 子表是抽样，不是主表全量；
- 存在错漏、未完成项、话术与分类错配；
- 模板是书面话术，不是真人对话；打断、情绪对抗、临场应变需要另行构造。

因此：

- 知识库保留原文模板，但 Agent 不直接把整段书面模板念给商家；
- 评测集覆盖电话/京麦、原因/整改、回电/投诉，而不是只测“背话术”；
- 真实业务系统写回、真实工单、真实外呼结果仍需接入，当前 `callback.create` 只是 Mock。
