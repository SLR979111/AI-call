一、赛题背景
  我国联络中心坐席规模约 440 万人，生态带动就业约 1000 万人，电话仍
是高时效、强意图业务的主动触达主通道。2026 年京东全球科技探索者大会
（JDD）发布“京东百灵数字员工”，其中外呼数字员工以“AI 销冠”定位，
在某头部汽车品牌实现线索筛选、企微加粉、试驾邀约、门店排程全流程自动执
行，效能提升 2.5 倍；在高客单电商挽回场景，挽单率达 10.41%，高于人工坐
席 3—5 个百分点。行业侧实证同样充分：物业催缴外呼量提升 10 倍以上、人
力成本下降 50% 以上，某社区物业费收缴率由 72% 提升至 94%；快递派送场
景转人工量下降 70%，质检覆盖率由不足 1% 提升至 100%。但该场景仍存在
三大痛点，其一，产业 AI 普遍“投入巨大、产出甚微”，多数应用停留在能力
演示层面，无法交付可评估的业务结果；其二，真实外呼是“秒级延迟 + 随时
打断 + 双讲抗噪 + 情绪对抗 + 合规红线”叠加的高难度交互，通用对话框架
往往“能闲聊、不能办事”；其三，优秀坐席的经验沉淀在个人身上，难以转化
为可复用、可自进化的数字资产。
  本赛题把企业真实外呼业务搬进校园，用“能不能对结果负责”作为验收标
尺，让学生在真实约束下完成语音识别与合成、实时音视频工程、任务型 Agent
编排、系统工具调用到自进化闭环的完整实践，为产业储备既懂算法、又能交付
的复合型人才。

二、赛题考察点及技术创新
  本赛题重点考察“实时语音交互、任务型 Agent 与自进化”三位一体的端到
端系统能力，强调能否在真实业务场景中完成任务，而非单一算法指标。参赛方
案应具备完整的实时语音交互能力，包括流式语音识别与端点检测、领域词表定
制、自然语音合成、端到端时延优化、打断响应、回声消除、双讲抗噪及 WebRTC
弱网传输；能够实现意图识别、槽位填充、对话状态管理、长会话记忆、任务规
划、幻觉抑制、合规话术校验、情绪安抚、转人工及异常兜底；支持通过 Function
Calling 或 MCP 等方式调用名单、订单和工单系统，完成结构化结果回写，并保
障调用的幂等性与一致性。同时，系统应具备全量会话转写、合规检测、指标看
板、失败归因和知识缺口挖掘能力，并做到一键启动、日志完整、实验可复现，

能够对时延、成本和质量之间的权衡进行量化分析。
  在此基础上，本赛题鼓励探索 RSI 自进化能力，将实时语音交互与持续优化
闭环贯通：系统可自动生成测试用例和包含对抗性场景的模拟用户，结合规则评
分与 LLM-as-Judge 构建可复现的评测基线，通过失败聚类与归因，自动优化提
示词、业务话术、检索知识和工具调用策略，并借助版本管理、回归验证和安全
回滚机制，确保进化后的整体指标优于原有基线。同时，方案还应注重泛化能力，
避免对已知测试集过拟合，使其在未公开场景中仍能保持稳定表现。Agent 不仅
要在真实外呼中“把事办成”，还要利用自身产生的对话数据持续提升下一版本
的能力，这是从“AI 工具”迈向“数字员工”的关键一步，也是本赛题区别于
常规语音对话赛题的核心创新点。

三、参赛要求
  （一）参赛对象。北京地区普通高等学校在校本科生，不限制专业和年级；
需以团队形式参赛，每支参赛队伍由 3—5 名队员组成，每支队伍的指导教师不
多于 2 人。
  （二）能力建议。鼓励跨专业组队，建议队伍整体至少覆盖以下 2 类能力：
      大模型应用开发：Prompt 工程、Tool-use/Function Calling、RAG、
  Agent 编排
      语音算法基础：ASR/TTS/VAD 原理，或具备调用与调优主流语音服
  务的能力
      Web 前端与实时音视频：WebRTC、JavaScript/TypeScript
      后端与工程化：Python/Node.js、服务部署、日志与评测体系建设
  （三）作品边界。参赛作品须由参赛队自主完成。允许使用开源框架与预训
练模型，但须在技术方案书中标注来源与许可证；不得将成品化的“整机外呼机
器人”商业产品直接用于完成核心任务。

四、赛程赛制
  （一）总体赛制。本赛题按“高校校赛推荐 — 企业分赛场选拔 — 北京市
线下决赛”三个阶段组织实施，遵循大赛总体时间安排。企业选拔赛不设淘汰环
节，按最终得分排名。

五、赛事规则与评分标准
  （一）总体规则。
  “企业选拔任务”考察“能不能把语音外呼数字员工做出来并跑通”。企业
选拔任务先行开展线上预选，参赛队伍完成任务后须提交技术方案书、演示视频
及测试集录音音频，由评审团队进行评议，形成参与企业线下选拔队伍名单，最
终形成推荐进入总决赛的队伍名单。
  （二）企业选拔任务.
  任务描述：基于 WebRTC 网页端构建一套完整的语音外呼客服数字员工，
在给定业务场景下完成真实外呼任务闭环。
  给定场景：服务类外呼场景，报名完成后公布详细背景资料及业务场景细节。
  基础完成门槛（不满足者不进入排名）：
     1. 浏览器端可与 Agent 完成不少于 3 轮连续实时语音对话，端到端
 首字响应时延 P50 不超过 2 秒
     2. 至少完成 1 个完整外呼任务闭环：开场自报身份 → 身份确认 →
 需求确认 → 方案或权益沟通 → 结果确认 → 结构化结果回写
     3. 无严重合规违规（辱骂歧视、虚假承诺、诱导、泄露他人隐私、使
 用禁用话术）

（三）作品内容限制。
      1. 允许使用开源代码、开源框架与预训练模型，须在技术方案书中标
 注来源与许可证；不允许直接使用成品化商业“外呼机器人”产品完成核心
 任务。
      2. 禁止硬编码评测集答案或针对已知测试用例做特判，评审将使用未
 公开测试集，并在现场随机抽测。
      3. 成果涉及语音、文本等内容时，须符合知识产权、数据安全、个人
 信息保护、AI 生成合成内容标识及公序良俗要求，不得包含涉密信息。
      4. 赛后须提交全部源代码以供查重，查重不通过者取消成绩。
  （四）排名与同分处理。
  按综合得分由高到低排序。同分情况下依次比较：① RSI 进化有效性得分；
② 实时语音交互质量得分；③ 现场加试一轮对抗性场景表现。

七、安全及风险提示
  （一）数据安全。赛题提供的业务资料、名单与对话数据均为脱敏或合成数
据，仅限本次大赛使用，不得外传、不得用于任何商业用途；现场测评数据赛后
统一回收销毁。
  （二）内容安全。Agent 输出须受合规话术约束，禁止生成辱骂、虚假承诺、
诱导及违法违规内容；一经发现，当场扣减该项得分，情节严重者取消参赛资格。

  （三）操作安全。使用云端大模型或语音 API 时须做好限流与费用控制；
现场严禁私自搭建外网穿透、代理，或进行大规模并发外呼。
  （四）合规与伦理。遵守《生成式人工智能服务管理暂行办法》《人工智能
生成合成内容标识办法》《个人信息保护法》及相关安宁权规定；演示内容须尊
重文化差异与公序良俗。
  （五）现场风险。长时间语音演示请佩戴耳机并控制音量，避免听力损伤；
比赛期间如出现系统故障、硬件异常或网络中断，应立即告知现场技术负责人协
同处置，不得自行拆装赛场设备。
