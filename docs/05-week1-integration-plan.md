# 05 · 第一周集成主线（Integration Spine）

> Owner：天命
> 目标：**Week 1 结束前，四端（前端/语音/Agent/评测）已经接在同一条可运行的主线上**，而不是各自跑通。
> 原则：先接口后实现，先骨架后功能，先跑通后优化，先可测后自进化。
> 计时：以团队启动日为 D0，不绑定具体日期。

---

## 1. 三周主线（先看全局）

| 周 | 主线 | 必须达成的硬结果 | 明确不做 |
|---|---|---|---|
| W1 | **集成脊柱** | Fake 全链路 → 真实 ASR/TTS/Agent 接入；一条会话可回放；首字时延有数 | 不做 RSI、不做多场景、不做模型调优 |
| W2 | **业务闭环 + WebRTC** | 六阶段闭环 + 工具回写；WebRTC 通；合规守卫上线；D 可批量跑 | 不做长期记忆、不做复杂 RAG |
| W3 | **稳定 + 证明进化** | P50/P95 达标；RSI 一组 A/B；一键启动；3 分钟演示 | 不做新功能，只做收敛与证据 |

> **提交物并行**：W1 必须启动 `THIRD_PARTY.md`、技术方案书大纲、评测集 v0、测试音频方案（见 [08 提交物](08-submission-package.md)）。不要等系统完成再写材料，否则 W3 一定爆。
>
> **关键路径**（任何一项延期都会拖垮比赛）：

```text
契约冻结 → Fake 骨架 → 真实语音 → WebRTC → 六阶段闭环 → 合规 → 时延收敛 → RSI 对比 → 演示
```

> **并行轨道（模型接入）**：LLM 云（[07](07-cloud-api-plan.md)）+ ASR/TTS 本地（[06](06-gpu-inference-plan.md)）。D1 拿 LLM Key 并测网络；SinCircle 同时起本地 ASR/TTS，D3 接真实语音。GPU 主机可达性是 P0；它**不替代** Fake 骨架 Gate。
>
> **如果进度落后，按此顺序砍**：

1. 长期记忆、复杂 RAG 重排；
2. 本地大模型（保留云 API + 预置话术降级）；
3. TTS 音色克隆/多音色；
4. 多工具（保留 2 个：查询 + 写入）；
5. RSI 自动搜索（保留「1 个候选 vs 基线」的单次 A/B）。

**不能砍**：WebRTC、合规守卫、时延埋点、一键启动、事件日志。

## 2. W1 顺序计划（不绑定日历）

> 以下 D0–D5 是**顺序**，不是日历。大家按各自时间在一周内完成，不要求同时在线；只有集成窗口需要对齐。

### D0（半天）：契约会签，不写业务代码

| 事项 | 产出 | 完成标准 |
|---|---|---|
| 开 60 分钟契约会 | 03 文档逐节过 | 4 位 owner 无异议，或异议当场改 |
| 定媒体路径 | 决策记录 | WS 骨架先行，W2 换 WebRTC（见第 3 节） |
| 定合规责任 | RACI | pseudonym 出 `rules.yaml`，天命接调用点，湖中日月出测试 |
| 建仓库骨架 | 目录 + CI + `make` | `make contract-test` 可跑（允许全红） |
| 建群/看板 | 阻塞清单 | 每人按节点报「完成/阻塞/需要的接口」 |

**D0 不做**：不讨论模型选型、不写 Prompt、不装 GPU 环境。

### D1：Fake 全链路 + 事件日志

**天命**：

- 实现 `Orchestrator` 骨架：`SessionStarted → TurnStarted → AgentStarted → AgentSentence → TTS → TurnCommitted`。
- 实现 `EventBus`：JSONL 落盘 + SQLite 索引 + `seq`。
- 实现 `FakeAsr`（按钮触发 final）、`FakeAgent`（固定 3 句）、`FakeTts`（正弦波/预置 wav）。
- 提供 `POST /sessions`、`WS /ws/session/{id}`、`GET /sessions/{id}/events`。

**cx**：最小页面：连接、按钮「开始说话/结束说话」、字幕、播放、事件时间线。

**验收（D1 Gate）**：

- 浏览器点 3 次按钮，完成 3 轮，页面显示字幕；
- `events.jsonl` 有 ≥15 类事件，`seq` 连续；
- 回放页面能按时间线重放；
- `TurnLatency` 能算出 `e2e_ms`（即使是假的）。

> 这一天的价值：**证明契约能落地**。任何接口歧义在此暴露，改契约成本最低。

### D2：真实文本 Agent + 工具 + Headless 评测

**天命**：

- 实现 `ToolGateway`：注册表加载、schema 校验、超时、幂等 SQLite、错误码。
- 实现 `mock-business`：订单查询/改约、工单、名单；故障注入。
- 实现 `POST /sessions/{id}/text` 与 `POST /eval/sessions`（文本模式），复用同一 Orchestrator/Agent。
- 接入 pseudonym 的 `Agent.handle()`（先不接 LLM 也可，用规则 Agent 占位）。

**pseudonym**：按 03 第 6 节实现 `Agent`，先跑通「查订单 → 改约 → 结束」文本流程。

**湖中日月**：用 headless 跑 5 条场景，产出第一份 `metrics.json` 与失败列表。

**验收（D2 Gate）**：

- `curl` 建文本会话，4 轮完成改约，`result.json` 有结构化结果；
- 工具重复调用同幂等键，只产生 1 个工单；
- 湖中日月能独立跑批，不需要浏览器/麦克风；
- 至少 1 条失败用例被归因到具体模块。

### D3：真实语音接入（WS 版）

**天命**：

- 媒体适配：WS 二进制帧 → `AudioFrame`；下行 `audio_chunk` → 浏览器。
- 接 SinCircle 的 `AsrStream` / `TtsStream` 适配器。
- 客户端 `PlaybackFirstFrame` 埋点打通，产出第一条真实 `TurnLatency`。

**SinCircle**：提供可用的流式 ASR 与 TTS 适配器；VAD 事件；首包延迟数据。开发用 3090，交付用 CPU sherpa-onnx（见 09）。

**cx**：`AudioWorklet` 采集/播放，16k 上行、24k 下行；字幕与播放状态。

**验收（D3 Gate）**：

- 真实说一句话 → 2 秒内听到回答（哪怕内容一般）；
- `TurnLatency` 有完整 `t0..t9`；
- 连续 3 轮不崩；
- 记录第一版 P50/P95（允许不达标）。

> 从这一天起，**每次集成后出一份时延报表**。没有数据的优化一律不接受。

### D4：打断 + 合规 + 契约测试

**天命**：

- 实现 `ClientSpeechStarted → CancelRequested → CancelAcked → TurnAborted` 全链路。
- 下行音频按 `turn_id` 过滤；`flush` 队列。
- 在句级路径插入 `ComplianceGuard`（先接正则快路径）。
- 补 `contracts/` schema 与 4 条夹具，`make contract-test` 转绿。

**SinCircle**：`SpeechStarted` 检测与时间戳；TTS 取消生效。

**cx**：本地 VAD 立即静音；`local_muted` 上报；误打断恢复 UI。

**pseudonym**：`rules.yaml` 初版（必说 3 条、禁语 5 条、转人工 3 条）。

**湖中日月**：合规测试集 v0（20 条），统计召回/误杀。

**验收（D4 Gate）**：

- 在 Agent 说话第 2 句打断，300–500ms 内静音，无残留；
- 禁语测试集召回 100%，误杀 ≤10%；
- 契约测试全绿；
- 事件顺序断言通过。

### D5：集成演示 + 周 Gate 评审

**产出**：

- 3 分钟演示脚本 v0：开场 → 身份确认 → 需求 → 方案 → 确认 → 回写 → 结束。
- 一页指标：3 轮成功率、P50/P95、打断停止、工具成功、合规召回。
- 决策：W2 是否切 WebRTC；若 D3/D4 未达标，W2 第一优先级是补债，不是加功能。

**W1 Gate（进入 W2 的条件）**：

| 条件 | 标准 |
|---|---|
| 一条会话可回放 | `events.jsonl` + 时间线 UI |
| 真实语音闭环 | 3 轮，端到端有声音 |
| 首字有数 | `TurnLatency` 完整，P50 有值 |
| 打断可用 | 停止 ≤500ms（W2 收敛到 300ms） |
| 工具幂等 | 重放不重复建单 |
| 合规可触发 | 必说/禁语各命中 1 次 |
| headless 可用 | D 能独立跑批 |
| 契约测试 | 全绿 |

> 任何一项不达标：W2 不加新功能，先补 Gate。

## 3. 媒体路径决策：WS 先行，W2 换 WebRTC

| 方案 | 时间 | 风险 | 结论 |
|---|---|---|---|
| A. 直接上 WebRTC（LiveKit） | D1–D3 | 媒体服务、Token、TURN、数据通道一起调，阻塞四端 | **不选**：把最高风险放在最缺契约的第一天 |
| B. WS 音频骨架 → W2 换 WebRTC | D1 通，D7–D9 换 | 换传输时契约不变，风险可控 | **推荐** |
| C. 全程 WS，不做 WebRTC | — | 不满足赛题「WebRTC 网页端」 | **不可选** |

**决策**：

- D1–D5 用 WebSocket 传 PCM（base64 或二进制），**接口按 03 第 4.2 节**。
- W2 D8–D9 替换为 WebRTC：媒体服务由天命负责（LiveKit 自托管优先；若 D7 前搞不定 TURN，退 aiortc + coturn）。
- 控制面 JSON 消息不变；音频从 `audio_chunk` 切到 WebRTC 音频轨。
- 切换前先做一天「双栈」：WS 与 WebRTC 同时可跑，用配置开关切，确认回滚路径。

**为什么不是一开始就 WebRTC**：不是技术偏好，是**风险排序**。契约未冻结时引入 ICE/TURN/编解码，会把「接口问题」和「媒体问题」混在一起，排障成本翻倍。

## 5. 每周节奏与阻塞升级

不设每日站会。学生按各自时间推进，**每周固定一次集成窗口**即可。

| 节奏 | 事项 | 产出 |
|---|---|---|
| 每周一次（时间自定，建议周末） | 集成窗口 60–90 分钟 | 当天只联调，不开发 |
| 每次集成后 | `make smoke` + 时延报表 | 通过/失败清单 |
| 每周一次（可与集成合并） | 3 分钟演示 + Gate | 录屏 + 指标页 |
| 日常 | 群里异步报「完成/阻塞/需要接口」 | 不要求秒回 |

**阻塞升级规则**：

- 接口歧义 >半天未决 → 天命拍板并写契约变更。
- 外部依赖（云 API/模型）>1 天不可用 → 切 Fake/备用，不等待。
- 某人模块 >2 天阻塞联调 → 天命提供 Fake 实现，先解耦。
